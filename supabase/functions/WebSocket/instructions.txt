SECTION 3 — DEPLOY PROD GCP WEBSOCKET SERVICES
--------------------------------------------------------------------------------

These are 3 Node.js Cloud Run services (WebSocket servers).
Source code is in: supabase/functions/WebSocket/

Get the prod Supabase service_role key first:
  supabase projects api-keys --project-ref iywivotqnphrjijztxtu

--- 3a. addressverification (us-central1) ---

  gcloud run deploy addressverification \
    --source supabase/functions/WebSocket/addressverification \
    --project doorknockerplus \
    --region us-central1 \

SECTION 6 — WHAT WAS CHANGED (security hardening, April 2026)
--------------------------------------------------------------------------------

These changes removed all API keys from front-end request bodies/headers/messages
so secrets are only held server-side.

Edge Functions (supabase/functions/) — keys moved from request headers to env vars:
  - verifyAddresses       : x-postgrid-api-key   → POSTGRID_API_KEY
  - createCampaign        : x-linkly-api-key/id  → LINKLY_API_KEY / LINKLY_WORKSPACE_ID
  - linkQRCodeToCampaign  : x-linkly-api-key/id  → LINKLY_API_KEY / LINKLY_WORKSPACE_ID
  - getAnalyticsPageData  : x-linkly-api-key/id  → LINKLY_API_KEY / LINKLY_WORKSPACE_ID
  - syncLinklyAnalytics   : x-linkly-api-key/id  → LINKLY_API_KEY / LINKLY_WORKSPACE_ID
  - getAddressesFromZone  : x-google-api-key      → GOOGLE_MAPS_API_KEY

WebSocket Services — keys moved from WS message body to process.env:
  - addressverification       : postgrid_api_key + supabase_anon_key removed from message
  - postcardsendingsocket     : postgrid_api_key removed from message; hardcoded anon key removed
  - findaddresses             : hardcoded service_role key fallback removed
  - address-verification-test : same as addressverification
  - postcardsendingsocket-test: same as postcardsendingsocket
  - find-addresses-openmaps   : hardcoded service_role key fallback removed
  - findadresses-test         : hardcoded service_role key fallback removed
